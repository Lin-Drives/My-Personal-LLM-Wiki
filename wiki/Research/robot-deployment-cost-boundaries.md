# 研究主线｜机器人策略怎样满足实际部署约束？

## 来源

- [arxiv-2609.33007](../../raw/Embodied-Intelligence/2609.33007.fulltext.md)

- [arxiv-2609.39403](../../raw/Embodied-Intelligence/2609.39403.fulltext.md)

## 概述

> 自动研究首轮草稿，未独立核验；不是作者个人判断或完整领域综述。

机器人控制频率、基础模型调用频率和最终策略推理延迟是不同量。CAPEX 的成本结果主要描述自动演示采集效率；IronMind 的辅助分支移除说明哪些训练计算不进入部署，但本轮没有形成跨硬件的延迟或功耗结论。

## 比较与证据

### 阅读前需要知道

底层控制负责按固定节奏执行运动指令；高层模型可以较稀疏地生成一段动作。动作分块能减少模型调用，但执行期间仍可能遇到观测滞后或突发接触，不能仅以平均调用减少判断闭环安全。

### 原文证据

CAPEX 在方法 §3（PDF p.3）说明机器人控制以 20 Hz 运行，基础模型只在稀疏决策点调用。方法 §3.1（p.4）将高层推理与 waypoint 执行分开，采用经验适应来决定何时再次推理。这里的 20 Hz 不是大模型每秒推理 20 次，也不是最终学生策略的实测延迟。[^arxiv-2609.33007]

在 18 个 RoboCasa 任务、360 个匹配起点的模拟比较中，ASTRA+CAPEX 成功 193 次（53.6%），基线成功 45 次（12.5%）；论文报告成功演示数量约 4.3 倍，以及每条成功演示 API 成本下降 80%。实验 §4.1–4.2（p.6）说明按全部尝试的 API 总成本除以成功演示数量计费，使用 2026-09-22 标价。不能把这些结果改写为“机器人总部署成本下降 80%”，也不能直接推广到所有真机任务。[^arxiv-2609.33007]

IronMind 方法部分（PDF p.4）说明辅助预测分支在推理时移除，不在部署时运行视频生成器。本轮核对支持“该辅助分支不进入推理”，不支持由此推断整套策略的具体延迟、功耗或安全性。[^arxiv-2609.39403]

## 局限性

### 尚未确认与下一轮

未独立核对 CAPEX 真机各任务的全部对照；上述 4.3 倍与 80% 只在明确列出的模拟比较范围内使用。下一轮从附录抽取硬件、模型调用时间、通信依赖与失败恢复规则。当前未找到可用于两篇之间严格比较的统一端到端延迟和功耗数据。

## 综合判断

建立部署证据表时，应分别记录底层频率、高层调用频率、单次模型延迟、动作 chunk 时长、观测到执行延迟，以及超时后的控制行为。成本也分采集期、训练期与部署期，标明是否包含硬件、网络或人工成本。
